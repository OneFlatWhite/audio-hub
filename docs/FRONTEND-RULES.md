# audio-hub 前端开发规则(v1,2026-11-12)

> 依据:WCAG 2.2 AA、Nielsen 十大可用性启发式、Material 3 令牌分层思想,
> 结合本项目约束(Jinja2 服务端渲染 + 原生 JS、无框架无 CDN、NAS 离线可用)。
> **每条规则都可检查**;违反 = 不合入。改 UI 的 PR/提交必须逐条对照 §6 清单。

## 1. 信息架构

1. 侧边栏分组 ≤ 5 个,每组入口 ≤ 5 个;入口名 = 用户语言(「待我确认」not「待审队列」)
2. **一页一事**:页面标题 = 用户要完成的任务;一页超过两屏即考虑拆分或折叠
3. **配置跟着使用走**:功能的凭据/参数放在功能页(设置抽屉/tab),设置页只留系统级
4. 同一实体(一部剧)的信息只有一处主视图,其他位置跳转过去,不复制

## 2. 组件

1. 表单:`<label for>` 强制关联;输入框必有可见标签;长解释收进 `title`/`<details>`,
   不平铺 hint;一个分组一个「热生效/需重启」标记,不逐行重复
2. 低频/高级配置(备用通道、内网回调)默认 `<details>` 折叠,标题旁一行状态摘要
   (「已配置 · 上次成功 2h 前」)
3. 危险操作(删除/丢弃/清除/切实跑):红色 + 二次确认,确认文案说明后果
4. 反馈:保存成功/失败用局部 toast(`data-autohide` 已有),禁止整页 flash 跳转打断
5. 空状态 = 引导卡:说明 + 「第一步 →」按钮链;禁止只写「暂无数据」
6. 列表 = 三件套:表头、行 hover、状态 pill(色点+文字双编码);>5 列收次要列进详情
7. 移动端 ≤768px:单列、侧边栏变抽屉、表格允许横向滚动但主操作常驻

## 3. 视觉令牌

1. 只用 `:root`/`[data-theme=dark]` 的 CSS 变量,禁止模板/JS 里写死颜色
2. 间距 = 4 的倍数;字号 12/14/16/20 四级;圆角 10/7 两档
3. 语义色唯一:蓝=主操作/链接,绿=正常,琥珀=注意,红=**仅危险**;禁止红色装饰
4. 层级靠边框和灰阶,阴影仅浮层;背景一律实色,禁止渐变与玻璃

## 4. 可访问性(WCAG 2.2 AA)

1. 每个输入控件有可访问名(label/aria-label)——`axe` 零「form label」违规
2. 正文对比度 ≥ 4.5:1;状态不只靠颜色(双编码,§2.6)
3. `:focus-visible` 可见;所有操作键盘可达(Tab 序 = 视觉序)
4. 图标按钮必有 `aria-label`;表格有 `<caption>`/标题关联
5. `prefers-reduced-motion` 时关闭过渡动画

## 5. 代码规范

1. 模板:语义 HTML5(`nav/main/table/details`),Jinja 逻辑 ≤ 简单循环与条件,
   复杂块抽 `{% include %}` 局部;一个局部只做一件事
2. JS:原生、无构建;事件绑定用 `data-*` 钩子;禁 `console.log` 入库;
   `fetch` 统一走 `app.js` 的 CSRF 封装;GET 表单不注 token(既有约定)
3. 静态资源引用必须带 `?v={{ version }}`;CSS 选择器 BEM-ish(`.lackfill-table`),
   禁止跨页面复用的样式写页面专属类
4. 行话(H&R/核销/洗版/熔断/DRY-RUN)首次出现加 `<abbr title>`;同页术语一致
5. 模板改动必须过**渲染测试**(集成测试真实渲染,parse 通过≠渲染通过,历史教训)

## 6. 合入前清单(逐条打勾)

- [ ] 空状态是引导卡(截图为证)
- [ ] 所有输入有可访问名;键盘走查一遍
- [ ] 危险操作有红+确认;反馈是 toast 不跳页
- [ ] 新颜色只用令牌;红未用于非危险场景
- [ ] 高级/低频配置已折叠,有状态摘要
- [ ] 集成渲染测试 0 failed;`?v=` 已更新
- [ ] 术语与全站一致(见 UI-REDESIGN.md §1)
