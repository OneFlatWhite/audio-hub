# audio-hub UI 重设计规范(v0.20 「任务流」改版)

> 背景:2026-11-12 用户评审——「设计 low、页面割裂、不友好」。根因:16 页由 5 个历史批次
> 各自实现,信息架构是开发者视角,行话无解释,空状态无引导,玻璃/实色混用。
> 本文档是 v0.20 全面改版的准绳;分四阶段落地,每阶段测试全绿才进下一阶段。

## 1. 信息架构(导航)

侧边栏按**用户任务流**分四组 + 总览置顶(已落地 v0.19 后续分支):

```
总览
找内容      发现墙 · 新上架 / 我的订阅 / 连载追踪
下载与入库  任务记录 / 待我确认(badge) / 做种 · H&R / 隔离区(badge)
资料库      已入库 / 补缺集
系统        站点凭据 / 下载器 / 事件 / 日志 / 设置
```

命名规则:**用户语言,不用系统语言**——「待审队列」→「待我确认」,「命中记录」→「任务记录」,
「缺集补齐」→「补缺集」。

## 2. 视觉令牌(已落地:实色分层,弃珍珠玻璃)

- 材质:全部实色平面,禁止渐变卡/玻璃 blur;层级靠**边框 + 灰阶**不靠阴影
- 主操作 `--accent` = 蓝(明 #1d4ed8 / 暗 #6d9bff);**红色只表危险**(删除/丢弃/失败)
- 状态三色 + dim 底,永远 pill「色点+文字」双编码
- 圆角 10/7 两档;阴影仅两级且克制;等宽字体只给数字/编码/时间
- 深浅双主题同语义切换

## 3. 每页规范(铺开时逐页对照)

1. **页首**:H1 + 当前任务一句话(不是模块名)+ 主操作按钮右上
2. **空状态 = 引导卡**:必须带「第一步 →」按钮链(如:先配站点凭据 → 测试认证 → 加订阅),
   禁止只写「暂无数据」
3. **术语**:首次出现的行话(H&R/核销/洗版/熔断/DRY-RUN)加 `<abbr>` 悬停解释;设置页顶部放术语表入口
4. **表单**:`<label for>` 强制关联;危险提交二次确认弹层;保存成功用局部 toast 不整页跳
5. **列表**:统一表格三件套(表头吸顶/行 hover/状态 pill);超过 5 列必须收次要列进详情
6. **补缺集页(v0.20 重点)**:改「缺集任务流水」单表——每行一部剧
   (缺 X 集 → 来源进度 → 转存 → CD2 → 核销),技术通道(爱影/Re0/CD2)细节折叠进行内详情,
   不再按通道分区

## 4. 阶段计划

- P1 样板间:令牌 + 侧边栏 IA(本分支)+ 总览页密度收敛
- P2 总览/补缺集两页按 §3 重排(旗舰样板,用户验收视觉方向)
- P3 全部列表页套三件套 + 空状态引导 + label 关联
- P4 设置/站点/下载器向导化 + 移动端抽屉导航 + 术语 tooltip

## 5. 验收口径

- 全量 pytest 保持 0 failed(页面渲染由集成测试兜底)
- 每阶段截图入 Obsidian 开发日志;用户过目后进下一阶段
